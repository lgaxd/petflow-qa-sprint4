CT-S4-14 — Evento de saúde com data futura

Teste planejado e objetivo

garantir que um evento marcado como REALIZADO não pode ter data futura (agendado pode).

Pré-condições

tutor A com Thor QA.

Dados de entrada

Consulta de Retorno · data = hoje + 30 dias · status REALIZADO.

Procedimento / passos de teste

  1. Em Eventos de saúde, criar o evento com os dados acima.
  2. Salvar.

Dados de saída esperados

  • Mensagem Um evento realizado não pode ter data futura; evento não criado.
  • (API) POST /health-events → 422, code = FUTURE_DATE_NOT_ALLOWED.
  • Saldo inalterado.

Rastreabilidade

  • PBI(s) validado(s): PBI-79
  • Teste automatizado: coleção Postman (automação API)
  • Massa de dados controlada e especificação completa: docs/casos-de-teste-manuais.md
